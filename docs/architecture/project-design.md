## 4. Execution Path — Boot → Request → Response

### 4.1 Boot sequence (`backend/server.js`)
1. `dotenv` loads env. **Hard fail** `process.exit(1)` if `JWT_SECRET` missing (fail-fast).
2. Build Express app; mount edge middleware (helmet → compression → cors → cookieParser → json/urlencoded 15 MB).
3. Mount **public** routes first: `/api/auth`, `/api/health`.
4. Mount two special pre-auth handlers that verify the JWT manually:
   - `POST /api/store-issuance/auto-issue` — token in body, idempotency window 15 s, delegates to `issuanceController.create`.
   - `POST /api/approvals/whatsapp-webhook` — inbound approval callback.
5. `app.use("/api", authenticate)` — **everything below is authenticated**.
6. Mount all 24 protected route modules (`/api/stock` … `/api/audits`, plus `/api` recipes).
7. `app.use(errorHandler)` — terminal error funnel (never leaks stacks).
8. `app.listen` callback → **auto-runs pending migrations** (`db.migrate.latest()`) then AI health check.
9. Register `node-cron` nightly anomaly job (`0 2 * * *`).

### 4.2 Authenticated request lifecycle
```
Request → helmet/cors/json
        → authenticate           # verify Bearer, load user, reject inactive → req.user
        → requirePermission(k)   # req.user.permissions.has(k) ? next : 403
        → validate(schema)       # zod; 400 on failure
        → controller             # dept-scope assert + Knex query
        → auditService.log()     # write before/after JSONB (non-blocking)
        → res.json({success,data})
Error at any step → errorHandler → {success:false,error} (401/403/400/404/500)
```

### 4.3 Response envelope (universal)
```json
{ "success": true,  "data": … }
{ "success": false, "error": "message" }
```

## 7. Security & RBAC Layer

- **Permission model** — `resource.action` keys (`stock.view`, `purchase_orders.approve`,
  `users.manage`…). Roles map to permission sets in seed/config; **application logic checks
  permissions, never role names**.
- **Primary roles** — Admin (all), Manager (dept-scoped oversight/approvals), Chef
  (kitchen workflows), Employee (task execution). Store Manager = restricted nav variant.
  New roles addable via DB seed **without code changes**.
- **Two-dimensional access** — *permission* (what action) × *department scope* (which records,
  via `user_departments`; Admin bypasses). List endpoints filter server-side — frontend filters
  are convenience only.
- **Sessions** — short-lived JWT access + opaque rotating refresh token stored **hashed** in DB,
  delivered as `httpOnly`/`secure`/`sameSite=strict` cookie. Password reset & deactivation revoke
  all refresh tokens.
- **Hardening** — bcrypt (cost 12), helmet headers, `express-rate-limit` on auth routes,
  no stack leakage, privilege-escalation guards (can't drop last admin, can't self-edit roles).
- **Frontend gating** — `PermissionGate` (hide actions), `ProtectedScreen` (block screens),
  permission-filtered `NAV_CATEGORIES`. **Visibility only — backend is the real gate.**

## 8. AI / OCR Subsystem (`services/localAI.js`)

- **Provider: Google Gemini** `gemini-3.5-flash` via `generativelanguage.googleapis.com`,
  key from `GEMINI_API_KEY`, `temperature 0.1`. (File header still says "Anthropic" — stale, §13.)
- **OCR: Tesseract.js in-process** with `eng/hin/tel.traineddata` — no external OCR call.
- **Speech: in-browser Whisper** (`@huggingface/transformers` in `whisper.worker.js`) — on-device
  multilingual capture; nothing leaves the browser for transcription.
- **Endpoints** — `/api/scan/indent`, `/api/scan/purchase`, `/api/scan/text`,
  `/api/approved-delivery/scan` → all RBAC-gated (`scan.*`, `approved_delivery.scan`).
- **Resilience** — `getMockFallback()` returns canned JSON when no key configured, so scan UI
  degrades gracefully. `checkAIHealth()` surfaces status at boot and via `/api/ai-health`.
- **Flow** — client uploads base64 image → controller → Tesseract OCR and/or Gemini parse →
  structured `{dept, date, items[]}` → validated → auto-populates form → user confirms → save.

## 9. Cross-Cutting Systems

- **Audit** (`auditService`) — every high-value mutation writes `audit_logs` with actor,
  resource, dept, before/after JSONB. Non-blocking: audit failure never rolls back a committed
  business txn (identity/role changes are the exception — wrapped in one txn).
- **Anomaly detection** — `cron/anomalyDetector.js` at 02:00 nightly → writes `anomaly_alerts`
  → surfaced via `/api/anomalies`.
- **Notifications** — `notifications` table + `NotificationPanel.jsx` for in-app alerts
  (low stock, reorder, approvals).
- **Approvals** — `approval_matrix` drives PO/workflow sign-off; inbound `whatsapp-webhook`
  lets approvers respond out-of-band.
- **Shift handoffs** — `shift_handoffs` + store-manager home for shift continuity.

## 10. Frontend Architecture

- **Entry** `main.jsx` → `App.jsx`. Screen-state router (`useState(currentScreen)`), **not**
  React Router. Nav categories filtered by `hasPermission`; unauthorized current screen falls
  back to first visible.
- **Contexts** — `AuthProvider` (user, roles, permissions, departments, `hasPermission`,
  login/logout/refresh) wraps `AppProvider` (shared masters: stock names, departments).
- **API client** (`api/client.js` + `authToken.js`) — injects `Authorization: Bearer`,
  `credentials:"include"`, on 401 tries `/api/auth/refresh` once then retries, normalizes 401/403.
- **Design system** — dark theme, `COLORS` single source (`styles/`), gold accent `#e8a838`,
  DM Serif Display + DM Sans. Reusable primitives: `Btn/Card/Input/Select/Section/Pagination/
  SearchBar/Badge`. Never hardcode hex.

## 14. Store Manager Ergonomics — "SM never blocked, Admin sees everything"

Design principle: never gate the store manager's speed, but log every mutation so admin
retains full oversight (segregation-of-duties without workflow friction).

**Already built (frontend `StoreManagerHome.jsx`):**
- Morning briefing card (AI-synthesized inventory status on login)
- Reorder alerts + predictive reorder + expiry-soon widget
- Shift handoff notes (`shift_handoffs` table, `/api/handoffs`) — AI-summarized activity log
  read/write, so night SM writes, morning SM reads
- SM nav restricted to Home / Available Stock / Purchase Order / Store Issuance / Indent Request

**Added this pass — admin visibility layer:**
- `stock.create` / `stock.edit` / `stock.delete` / `issuances.create` now write to `audit_logs`
  (before/after JSONB) via `services/auditService.js` — previously **zero** audit coverage on
  these mutation paths.
- Large adjustment/delete threshold alert (`ADJUSTMENT_ALERT_QTY = 50` units) pushes a
  `stock_threshold` notification to the Admin role in real time — SM action is never blocked,
  admin is pinged immediately (`controllers/stockController.js:alertAdminIfLarge`).
- Approval escalation cron (`cron/approvalEscalation.js`, every 30 min, 4h threshold) — if SM
  is unreachable, Admin gets escalated automatically; Admin also has a permanent approval
  bypass (`canApprove` in `approvalController.js`).

**Backlog (not built — flagged, not started):**
- Barcode/QR scan-to-adjust workflow
- One-tap "repeat last week's purchase" reorder
- Daily WhatsApp digest to admin (in + out + low stock)
- Weekly SM scorecard (issuance speed, shortfall rate, adjustment frequency)
- Photo-proof attachment on large adjustments

## 15. Observability & Event Bus — Kafka, Prometheus, Grafana

Local, native-Windows install (not Docker), rooted at `C:\infra`:

| Component | Location | Port | Status |
|---|---|---|---|
| Kafka 4.0.2 (KRaft, no Zookeeper) | `C:\infra\kafka` | 9092 (broker), 9093 (controller) | configured + storage formatted |

**One remaining manual step:** Kafka and Prometheus need registering as Windows
services via NSSM, which requires Administrator rights this agent doesn't have.
Run `C:\infra\install-services-admin.ps1` once from an elevated PowerShell —
it wraps both as auto-start services and starts them. Java 17 (`Microsoft.OpenJDK.17`)
and NSSM are already installed.

**Event bus wiring (`backend/services/kafkaProducer.js`)** — lazy-connect,
fail-safe (same contract as `auditService`: broker down never breaks a
mutation, just logs a warning). Topics published today:

| Topic | Fired from | Event types |
|---|---|---|
| `stock-events` | `stockController.js` | `stock.create`, `stock.edit`, `stock.delete` |
| `indent-events` | `indentController.js` | `indent.create` |
| `issuance-events` | `issuanceController.js` | `issuance.create` |

No consumers built yet — topics exist for future use (e.g. a real-time low-stock
dashboard, an external ERP bridge, or a Grafana Kafka-lag panel). `KAFKA_BROKER`
env var (default `localhost:9092`) points the producer at the broker.

**Metrics (`GET /metrics` on the backend, :3001)** — `prom-client` default
Node.js process metrics (`kapila_` prefix) + `kapila_http_request_duration_seconds`
histogram per route/method/status. Prometheus scrape config
(`C:\infra\prometheus\prometheus.yml`) already points at `localhost:3001/metrics`.

**Next step for Grafana:** add Prometheus (`http://localhost:9090`) as a
datasource once both services are running, then build panels off
`kapila_http_request_duration_seconds` and the default process metrics.
